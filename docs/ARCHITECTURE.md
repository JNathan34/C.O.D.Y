# Architecture

The current application lives in `CODY-App`. Its Electron main process starts the local Windows engine and connects the island renderer through isolated preload APIs and IPC.

```text
Island renderer / Settings
        |
Isolated preload API
        |
Electron main process
  +-- Account and assistant adapters
  +-- Local utilities, capture and overlays
  +-- GitHub update service
  +-- Permission-controlled Windows tools
        |
Native engine over a profile-scoped named pipe
  +-- Voice and wake-word integration
  +-- Native background tasks
  +-- Browser and Windows integration
```

`frontend/original-cody/src/main.js` owns app startup, IPC registration and shutdown. `src/island/renderer` contains the active interface. `src/native-engine.js` resolves and starts the bundled engine. Native sources are under `work/Cody.*`; recovered runtime dependencies are restored separately from the versioned build-input asset.

The updater uses electron-updater and NSIS metadata generated by electron-builder. It checks public releases at JNathan34/C.O.D.Y, rejects downgrades and prereleases, validates download checksums, and waits for an explicit install action. It stays disabled in development copies. The old engine updater stays disabled.

The installed application keeps chats, account data and preferences in the existing CODY-Integrated Windows user profile. Profiles, tokens, recordings and diagnostic reports are excluded from the source repository and build-input bundle.
